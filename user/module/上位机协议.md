# 上下位机串口协议 v0.1

> 实现：`user/module/host_protocol.{hpp,cpp}`（编解码）+ `user/app/task/host_task.cpp`（收发与执行）

## 1. 物理层

| 项 | 值 |
| --- | --- |
| 端口 | USART10（PE2 = RX，PE3 = TX） |
| 参数 | **921600 8N1**，DMA 收发 |
| 建议发送周期 | 速度指令 100 Hz；其余按需 |

## 2. 帧格式

```
0xAA 0x55 | VER | TYPE | SEQ | LEN | PAYLOAD … | SUM
   帧头      版本   类型   序号   长度     载荷       累加和
```

| 字段 | 字节 | 说明 |
| --- | --- | --- |
| `0xAA 0x55` | 2 | 双字节帧头 |
| `VER` | 1 | 协议版本，当前 `0x01` |
| `TYPE` | 1 | 消息类型（见下表） |
| `SEQ` | 1 | 序号，每发一条 +1（0~255 循环）；`ACK` 会回带 |
| `LEN` | 1 | 载荷长度，上限 48 |
| `PAYLOAD` | LEN | 载荷 |
| `SUM` | 1 | **累加和**：从 `VER` 到 `PAYLOAD` 末字节逐字节相加，取低 8 位（不含两个帧头字节） |

- 多字节数值一律**小端**（低字节在前）
- 收端建议：找 `AA 55` → 读 `LEN` → 凑满 `7 + LEN` 字节 → 校验 `SUM`；任一步失败**只丢 1 字节**重新找帧头

## 3. 上位机 → 车

| TYPE | 名称 | 载荷 | 说明 |
| --- | --- | --- | --- |
| `0x01` | `CMD_VEL` | `i16 vx`, `i16 vy`, `i16 wz` | **车体系**速度：cm/s、cm/s、**mrad/s**；100 Hz 持续发 |
| `0x02` | `CMD_VEL_TIME` | `i16 vx`, `i16 vy`, `i16 wz`, `u16 dur_ms` | 以该速度跑 `dur_ms` 后自动停车，完成时回 `MOVE_DONE` |
| `0x03` | `CMD_MOVE` | `i16 x_cm`, `i16 y_cm`, `i16 yaw_0p1deg`, `u8 ref` | 近似位置动作（见 §6）。`ref=0` 车体系，`ref=1` 场地系 |
| `0x04` | `CMD_SERVO` | `u8 id`, `u16 angle_0p1deg` | `id=1/2`；角度 `0~2700` 对应 `0~270°` |
| `0x05` | `PING` | 无 | 车回 `PONG`（带运行时长），用于判活 / 测往返 |
| `0x06` | `CMD_TASK` | `u8 task_id`, `u8 arg` | 任务 1/2/3 **预留**，当前回 `RES_UNSUPPORTED` |
| `0xFF` | `ESTOP` | 可省（`u8 reason`） | 急停：立即停车 + 清运动任务，回 `EVENT` 与 `ACK` |

## 4. 车 → 上位机

| TYPE | 名称 | 载荷 | 频率 |
| --- | --- | --- | --- |
| `0x00` | `ACK` | `u8 acked_type`, `u8 acked_seq`, `u8 result` | 按需 |
| `0x01` | `FIELD_STATUS` | `u8 spawn_id`(1~4), `u8 safe_zone`(1/2) | 上电 1 次 + 变化时 |
| `0x02` | `STATE` | `u8 source`(0 RC/1 HOST/2 STOP), `u16 fault`, `u32 uptime_ms` | 上电 1 次 + 控制源变化时 |
| `0x03` | —— | **预留（未实现）** | —— |
| `0x04` | —— | **预留（未实现）** | —— |
| `0x05` | —— | **预留**（原 `SERVO` 反馈已删除：舵机无位置反馈，不传输，上位机自己记目标） | —— |
| `0x06` | `EVENT` | `u8 code`, `u8 data` | 事件触发 |
| `0x07` | `HELLO` | `u8 ver`, `u8 fw_major`, `u8 fw_minor` | 上电 1 次 |
| `0x08` | `MOVE_DONE` | `u8 cmd_type`, `u8 cmd_seq`, `u8 result` | 动作完成 |
| `0x0F` | `PONG` | `u32 uptime_ms` | 应答 `PING` |

`result`：`0` 成功 / `1` 帧格式错 / `2` 不支持 / `3` 当前模式拒绝。

**没有周期心跳，也不主动开遥测流**：下行只在有事时发 —— `ACK`、`MOVE_DONE`、`EVENT`，
以及 `STATE` / `FIELD_STATUS` 的**变化时**补发（`HELLO` 上电一次）。

- **判活**：发 `PING`（`0x05`），车会回 **`PONG` + `STATE` + `FIELD_STATUS` 三帧**，
  所以上位机随时 PING 一次就能拿到开机时长、当前控制源、出生点和安全区
- 下位机主循环是**事件驱动**的：串口一来数据就立即处理（不是定时轮询）

`EVENT code`：`2` 收到急停（其它事件码需要时再加）。

## 5. 控制权

- **遥控器优先**：CH5 三挡决定底盘听谁 —— `+100` 上位机、`0` 强制停车、`-100` 遥控
- **遥控器关掉 / 离线时控制权自动交给上位机**（丢掉遥控器最后的速度并停一次，之后上位机可以直接发指令开走）
- 只有当前控制源是上位机时，`0x01/0x02/0x03/0x04` 才会执行；否则回 `RES_REJECTED`
- 遥控器一拨走（切到遥控/停车挡），车上正在执行的运动任务立即中止并停车
- **没有超时保护**：上位机停发 `CMD_VEL` 时车保持上一次速度；要停车请发 `ESTOP` 或把 CH5 拨到中间挡

## 6. `CMD_MOVE` 的精度

车**没有位置环**，只有速度环 + WT102 的 yaw，所以按段近似执行：

1. 原地转到「运动方向」（yaw 闭环，这一段较准）
2. 以固定 `40 cm/s` 直行「距离 ÷ 速度」这么久（打滑 / 加减速会带来误差）
3. 原地转到目标朝向

- `ref = 0`（车体）：`(x, y)` 以**当前车头**为基准（`+y` 前、`+x` 右），`yaw` 是相对当前车头的转角
- `ref = 1`（场地）：`(x, y)` 与 `yaw` 都是绝对量（以 WT102 的 yaw 为 0°）
- 三段全部完成才回 `MOVE_DONE`；被新指令或急停打断则回 `MOVE_DONE(result=3)`

## 7. 报文示例

上位机发车体速度「前进 50 cm/s、不转」：

```
AA 55 01 01 07 06 32 00 00 00 00 00 3B
│  │  │  │  │  │  └──┴─ vy = 0
│  │  │  │  │  │        vx = 0x0032 = 50，vy = 0，wz = 0
│  │  │  │  │  └─ SEQ=7
│  │  │  │  └─ LEN=6
│  │  │  └─ TYPE=0x01
│  │  └─ VER=1
└──┴─ 帧头
SUM = 01+01+07+06+32+00+00+00+00+00 = 0x3B
```

车回应答（ACK，确认类型 0x01、序号 7、结果 0）：

```
AA 55 01 00 08 03 01 07 00 14
```

## 8. 出生点 / 安全区怎么设

车上用按键设定（不需要上位机下发）：

- **KEY1 短按**：出生点 `1 → 2 → 3 → 4 → 1` 循环（只改本地值）
- **KEY2 短按**：安全区 `1 ↔ 2`（只改本地值）
- **KEY1 / KEY2 长按**：把当前出生点 + 安全区**推送给上位机**（发一帧 `FIELD_STATUS`）

所以"第一次获得"由操作者按长键触发；之后上位机想再要，发 `PING` 即可。
串口 1 会打印 `[field] spawn=…` / `[field] safe_zone=…` / `[field] push spawn=… zone=…`。
