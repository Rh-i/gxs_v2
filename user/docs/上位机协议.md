# 上下位机串口协议

> 代码：`host_protocol.{hpp,cpp}` 编解码 · `host.cpp` 执行 · `host_task.cpp` 任务
> 测试工具：`tools/proto_test.py`（纯标准库，用法见 §13）

## 1. 物理层

| 项   | 值                           |
| ---- | ---------------------------- |
| 端口 | USART1（PB6 = TX，PB7 = RX） |
| 参数 | 921600 8N1，DMA 收发，无流控 |

## 2. 帧格式

```
0xAA 0x55 | TYPE | SEQ | LEN | PAYLOAD … | SUM | 0x0D 0x0A
   帧头      类型   序号   长度     载荷     累加和     帧尾
```

- 多字节数值一律**小端**。
- `SUM` = 从 `TYPE` 到载荷末字节的 8 位累加和（**不含**帧头、`SUM` 自身和帧尾）。
- `LEN ≤ 48`，一帧最长 8 + 48 = 56 字节。
- `SEQ` 每发一帧 +1（0~255 循环）；`ACK` / `MOVE_DONE` 会回带对方的 `SEQ`，方便配对。
- 收端（两侧同规则）：找 `AA 55` → 读 `LEN` → 凑满 `8 + LEN` 字节 → 校验 `SUM` 与 `0D 0A`；
  任一步失败**只丢 1 字节**重新找帧头，半帧会一直等到凑齐（不会误杀后面的好帧）。

## 3. 上位机 → 车

| TYPE     | 名称             | 载荷                                   | 长度   | 简单解释                                               | 备注                   |
| -------- | ---------------- | -------------------------------------- | ------ | ------------------------------------------------------ | ---------------------- |
| `0x01` | `CMD_VEL`      | `i16 vx, i16 vy, i16 wz`             | 6      | 按vx vy wz 一直跑                                      | 无回报                 |
| `0x02` | `CMD_VEL_TIME` | `i16 vx, i16 vy, i16 wz, u16 dur_ms` | 8      | 按vx vy wz 跑dur_ms的时间后停下                        | 回报                   |
| `0x03` | `CMD_MOVE`     | `i16 x_cm, i16 y_cm, u16 speed_cm_s` | 6      | 按x_cm y_cm的值，speed的速度，开环移动到对应位置后停下 | 回报                   |
| `0x04` | `CMD_SERVO`    | `u8 id, u16 angle_0p1deg`            | 3      | 给序号为id的舵机，发送角度 单位0-2700 对应270度舵机    | 舵机位置不可读，无回报 |
| `0x05` | `PING`         | 无                                     | 0      | 判活                                                   | 会回复PONG             |
| `0xAC` | `HOST_ACK`     | `u8 acked_type, u8 acked_seq`        | 2      | 上位机确认已收到场地信息                               | 车不回帧               |
| `0xFF` | `ESTOP`        | 可省 `u8 reason`                     | 0 或 1 | 急停                                                   | /                      |

### 3.1 `CMD_VEL`（0x01）持续速度

| 偏移 | 字段   | 类型    | 单位   | 建议范围   | 说明                             |
| ---- | ------ | ------- | ------ | ---------- | -------------------------------- |
| 0    | `vx` | `i16` | cm/s   | -200~200   | 车体系 **+x 向右**         |
| 2    | `vy` | `i16` | cm/s   | -200~200   | 车体系 **+y 向前**         |
| 4    | `wz` | `i16` | mrad/s | -3000~3000 | 俯视逆时针为正（1000 = 1 rad/s） |

- **发多少收多少，不做限幅。无回复帧。**
- **没有超时保护**：不发就保持上一次速度。停车请发 6 个 0，或者直接 `ESTOP`。
- 例：前进 20 cm/s → `AA 55 01 03 06 00 00 14 00 00 00 1E 0D 0A`

### 3.2 `CMD_VEL_TIME`（0x02）定时速度

| 偏移 | 字段       | 类型    | 单位   | 范围       | 说明                 |
| ---- | ---------- | ------- | ------ | ---------- | -------------------- |
| 0    | `vx`     | `i16` | cm/s   | -200~200   | 同 `CMD_VEL`       |
| 2    | `vy`     | `i16` | cm/s   | -200~200   | 同 `CMD_VEL`       |
| 4    | `wz`     | `i16` | mrad/s | -3000~3000 | 同 `CMD_VEL`       |
| 6    | `dur_ms` | `u16` | ms     | 1~65535    | 跑多久（到点自动停） |

- 长度必须 8，否则 `ACK(1)`。
- 行为：立刻按该速度跑，`dur_ms` 后自动停车，**停车时刻精度 1 ms**。
- 回帧顺序：`ACK(0)` → （到时）`MOVE_DONE(0x02, seq, 0)`。
- 中途被打断（新运动指令 / `ESTOP` / 遥控器抢回）→ `MOVE_DONE(0x02, seq, 3)`。
- 适合"直走 1 秒""原地转 90°"这类不需要精确落点的动作。
- 例：前进 20 cm/s 跑 1 s → `AA 55 02 04 08 00 00 14 00 00 00 E8 03 0D 0D 0A`

### 3.3 `CMD_MOVE`（0x03）按指定速度开到点 开环

| 偏移 | 字段           | 类型    | 单位 | 范围            | 说明                     |
| ---- | -------------- | ------- | ---- | --------------- | ------------------------ |
| 0    | `x_cm`       | `i16` | cm   | -3000~3000      | 车体系 **+x 向右** |
| 2    | `y_cm`       | `i16` | cm   | -3000~3000      | 车体系 **+y 向前** |
| 4    | `speed_cm_s` | `u16` | cm/s | **5~100** | 本次动作的直线速度       |

- 长度必须 6，否则回 `ACK(1)`。
- 速度越界**不报错，直接夹到 5 / 100**：太慢走不动、太快开环误差大。
- 回帧顺序：`ACK(0)` → （跑完）`MOVE_DONE(0x03, seq, 0)`；
  `d ≤ 0.5 cm` 时 `ACK(0)` 之后**立刻** `MOVE_DONE(0)`（不建任务）。
- 被打断（新运动指令 / `ESTOP` / 遥控抢回）→ `MOVE_DONE(0x03, seq, 3)`。
- 例：走 20 cm、40 cm/s（约 0.5 s）→ `AA 55 03 05 06 14 00 00 00 28 00 4A 0D 0A`
- 例：走 30 cm、30 cm/s（约 1 s）→ `AA 55 03 0B 06 1E 00 00 00 1E 00 50 0D 0A`

### 3.4 `CMD_SERVO`（0x04）舵机

| 偏移 | 字段             | 类型    | 单位  | 范围   | 说明                      |
| ---- | ---------------- | ------- | ----- | ------ | ------------------------- |
| 0    | `id`           | `u8`  | —    | 1 / 2  | 其它值回 `ACK(2)`       |
| 1    | `angle_0p1deg` | `u16` | 0.1° | 0~2700 | 1350 = 中位，2700 = 270° |

- 长度必须 3，否则 `ACK(1)`。
- 控制的是270度舵机。v2版本小车135度为上电角度，角度不要太大会碰到其他机构
- 回帧：`ACK(0)`（成功）/ `ACK(2)`（id 不对）/ `ACK(3)`（控制源不是上位机）。
- **无位置反馈**，上位机自己记目标角。
- 例：舵机 1 转到 135° → `AA 55 04 06 03 01 46 05 59 0D 0A`

### 3.5 `PING`（0x05）判活

- 无载荷。
- 只回一帧 `PONG`（12 字节，带开机毫秒数），**不附带** `STATE` / `FIELD_STATUS`。
- 用途：① 判断车在线；② 测往返时延；③ `uptime` 变小 = 车重启过。

### 3.6 `HOST_ACK`（0xAC）上位机确认

| 偏移 | 字段           | 类型   | 说明                                                           |
| ---- | -------------- | ------ | -------------------------------------------------------------- |
| 0    | `acked_type` | `u8` | 被确认那一帧的 `TYPE`，目前只用 `0x01`（`FIELD_STATUS`） |
| 1    | `acked_seq`  | `u8` | 被确认那一帧的 `SEQ`，车端只记录不参与判断                   |

- 上位机收到 `FIELD_STATUS` 后回这一帧，车就停止重发。
- 车收到 `0xAC` 不回任何帧。
- 不回也能用，车会把 10 帧发完（共 1 s）。

### 3.7 `ESTOP`（0xFF）急停

- 载荷 `u8 reason` 可选（目前不解析，填 0 即可；发空载荷也接受）。
- 立刻：停车 + 清 `CMD_MOVE` / `CMD_VEL_TIME`。
- 回帧顺序：`MOVE_DONE(..3)`（**有动作在跑时才发**）→ `EVENT(2)` → `ACK(0)`。
- **任何控制源下都生效**（遥控档也能停）。

## 4. 车 → 上位机

不做周期遥测、没有心跳：只在被问、状态变化、动作结束时发。

| TYPE     | 名称             | 载荷                                       | 长度 | 什么时候发                                   |
| -------- | ---------------- | ------------------------------------------ | ---- | -------------------------------------------- |
| `0x00` | `ACK`          | `u8 acked_type, u8 acked_seq, u8 result` | 3    | 每条上行指令（`CMD_VEL` 正常接受时除外）   |
| `0x01` | `FIELD_STATUS` | `u8 spawn_id, u8 safe_zone`              | 2    | 长按确认触发，100 ms × 10 帧                |
| `0x02` | `STATE`        | `u8 source, u16 fault, u32 uptime_ms`    | 7    | 上电 1 次 + 控制源变化时                     |
| `0x06` | `EVENT`        | `u8 code, u8 data`                       | 2    | 异步事件（目前只有急停）                     |
| `0x08` | `MOVE_DONE`    | `u8 cmd_type, u8 cmd_seq, u8 result`     | 3    | `CMD_MOVE` / `CMD_VEL_TIME` 结束或被打断 |
| `0x0F` | `PONG`         | `u32 uptime_ms`                          | 4    | 回复上位机发送的 `PING`                   |

### 4.1 `ACK`（0x00）指令应答

| 偏移 | 字段           | 类型   | 说明                  |
| ---- | -------------- | ------ | --------------------- |
| 0    | `acked_type` | `u8` | 被应答那帧的 `TYPE` |
| 1    | `acked_seq`  | `u8` | 被应答那帧的 `SEQ`  |
| 2    | `result`     | `u8` | 见 §4.7              |

- **什么时候没有 ACK**：`CMD_VEL` 在 HOST 模式下被正常接受时。
- 用于 `CMD_MOVE` / `CMD_VEL_TIME` 这类有时长的动作。
- 用途：让上位机确认指令已送达。收不到 `ACK` 时可以选择重发。
- 重发等于再执行一次。`CMD_VEL`、`CMD_SERVO`、`ESTOP`、`PING` 重复发送没有副作用；
  `CMD_MOVE`、`CMD_VEL_TIME` 重发会中止当前动作，从当前位置重新跑满整段距离或时长。
- `result=3` 说明指令合法，但当前不归上位机控制，不要重发，先看 CH5。
- `FIELD_STATUS` 的确认不走这一帧，用 §3.6 的 `0xAC`（方向相反）。

### 4.2 `FIELD_STATUS`（0x01）比赛信息

| 偏移 | 字段          | 类型   | 说明           |
| ---- | ------------- | ------ | -------------- |
| 0    | `spawn_id`  | `u8` | 出生点 1~4     |
| 1    | `safe_zone` | `u8` | 1 = 红，2 = 蓝 |

- 长按确认后立即发第 1 帧，此后每 100 ms 重发一次，共 10 帧（约 1 s）。
- 上位机收到后回一帧 `0xAC`（`acked_type=0x01`），车立即停止剩余重发。不回也能收到，只是多几帧重复数据。

### 4.3 `STATE`（0x02）控制源与运行时长

| 偏移 | 字段          | 类型    | 说明                                 |
| ---- | ------------- | ------- | ------------------------------------ |
| 0    | `source`    | `u8`  | 0 = 遥控 / 1 = 上位机 / 2 = 强制停车 |
| 1-2  | `fault`     | `u16` | 故障位图，目前恒 0（预留）           |
| 3-6  | `uptime_ms` | `u32` | 开机毫秒数                           |

- 上电发 1 次，之后**只在 `source` 变化时**发（CH5 拨挡、遥控掉线时会看到）。
- 上位机可以用它确认"现在到底谁在控制"

### 4.4 `EVENT`（0x06）异步事件

| 偏移 | 字段     | 类型   | 说明                                  |
| ---- | -------- | ------ | ------------------------------------- |
| 0    | `code` | `u8` | 事件类型，目前只有 `2` = 收到急停   |
| 1    | `data` | `u8` | 随 `code` 变化；`code=2` 时恒为 0 |

- `EVENT` 报告车上发生的事件，与指令应答无关。收到急停时，`ACK` 说明指令已被执行，`EVENT` 说明急停确实发生过，上位机可用它触发自己的停车逻辑并记录日志。
- 遇到不认识的 `code` 直接忽略。以后新增低电压、碰撞这类事件只扩展 `code`，帧格式不变。

### 4.5 `MOVE_DONE`（0x08）动作结束

| 偏移 | 字段         | 类型   | 说明                                                           |
| ---- | ------------ | ------ | -------------------------------------------------------------- |
| 0    | `cmd_type` | `u8` | 原始指令：`0x03` = `CMD_MOVE`，`0x02` = `CMD_VEL_TIME` |
| 1    | `cmd_seq`  | `u8` | 原始指令的 `SEQ`                                             |
| 2    | `result`   | `u8` | `0` = 正常跑完；`3` = 被打断                               |

- 只有"有时长的动作"会发：`CMD_MOVE`、`CMD_VEL_TIME`。**`CMD_VEL` 永远不会有 MOVE_DONE。**
- `ACK` 表示指令已被接受，`MOVE_DONE` 表示动作结束。上位机先等 `ACK` 确认接受，再等
  `MOVE_DONE` 确认结束，两步齐了再发下一条。
- 被打断的三种情况：新的运动指令、`ESTOP`、控制源被遥控器抢回。三种都会先回一帧
  `MOVE_DONE(result=3)`，`cmd_type/cmd_seq` 指向**被打断的那条指令**。

### 4.6 `PONG`（0x0F）判活回帧

| 偏移 | 字段          | 类型    | 说明                                  |
| ---- | ------------- | ------- | ------------------------------------- |
| 0-3  | `uptime_ms` | `u32` | 开机毫秒数（从 0 起，约 49.7 天回绕） |

- 只应答 `PING`，一帧 12 字节。
- 上位机判据：连续 3 次（约 0.5 s）收不到 → 认为掉线；`uptime` 突然变小 → 车重启过。

### 4.7 `result` 结果码（`ACK` / `MOVE_DONE` 共用）

| 值    | 含义         | 典型场景                                               | 上位机应该怎么做       |
| ----- | ------------ | ------------------------------------------------------ | ---------------------- |
| `0` | 成功         | 指令被接受 / 动作正常跑完                              | 继续                   |
| `1` | 帧错         | 长度不够（校验/长度错在解析层就被丢了，基本见不到）    | 检查载荷长度           |
| `2` | 不支持       | 不认识的 `TYPE`，或 `CMD_SERVO` 的 `id` 不是 1/2 | 对表                   |
| `3` | 当前模式拒绝 | CH5 不在上位机档；或被新指令/急停/控制源切换打断       | 先查控制源，别盲目重发 |

## 5. 控制权

- CH5 三挡：`+100` 上位机 / `0` 强制停车 / `-100` 遥控。遥控器掉线时控制权自动交给上位机，先停一次车。
- 控制源不是上位机时，运动类指令回 `ACK(3)`；正在跑的动作立即中止并回 `MOVE_DONE(3)`。
- 车没有指令超时保护。停车要么发 `ESTOP`，要么把 CH5 拨到停车挡。

## 6. 指令时序

| 指令                        | 回帧顺序                                                                                          |
| --------------------------- | ------------------------------------------------------------------------------------------------- |
| `PING`                    | `PONG`                                                                                          |
| `CMD_VEL`（HOST 模式）    | 无                                                                                                |
| `CMD_VEL`（非 HOST 模式） | `ACK(3)`，最多 5 Hz                                                                             |
| `CMD_VEL_TIME`            | `ACK(0)` → `MOVE_DONE(0)`，被打断则 `MOVE_DONE(3)`                                         |
| `CMD_MOVE`                | `ACK(0)` → `MOVE_DONE(0)` / `MOVE_DONE(3)`；`d ≤ 0.5 cm` 时 ACK 后立刻 `MOVE_DONE(0)` |
| `CMD_SERVO`               | `ACK(0)` 或 `ACK(2)`（id 不是 1/2）                                                           |
| `ESTOP`                   | `MOVE_DONE(3)`（若有动作）→ `EVENT(2)` → `ACK(0)`                                         |
| `HOST_ACK`（0xAC）        | 无                                                                                                |
| 未知 `TYPE`               | `ACK(2)`                                                                                        |

`FIELD_STATUS` 由长按触发，不属于指令，规则见 §4.2。

## 7. `CMD_MOVE` 精度

全向底盘不需要转向，指令给出方向、速度和距离后按时间开环执行：

$$
d = \sqrt{x^2+y^2},\qquad (v_x,v_y) = (x,y)\cdot\frac{\text{speed}}{d},\qquad t = d / \text{speed}
$$

`speed` 取 `speed_cm_s`，夹在 5~100 cm/s。没有位置环和陀螺仪，打滑、加减速、负载都会带来误差，落点通常差几厘米到几十厘米，速度越大误差越大。下位机只保证方向正确、速度量级正确、按时停车，位置和姿态闭环由上位机负责。

## 8. 比赛信息 下位机处理

- KEY1 短按切换出生点 `1→2→3→4→1`，KEY2 短按切换颜色（`safe_zone` 1 = 红、2 = 蓝）。
- OLED 四角数字显示出生点，`红` 在 1/2 之间、`蓝` 在 3/4 之间，选中的那一格反白。
- KEY1 或 KEY2 长按 0.6 s 推送 `FIELD_STATUS`，发送规则见 §4.2。上位机只能靠这一帧更新场地信息。

## 9. 报文示例

`PING`，`SEQ=01`：

```
AA 55 05 01 00 06 0D 0A
│  │  │  │  │  └─ SUM = 05+01+00
└──┴─ │  │  └─ LEN = 0
      │  └─ SEQ
      └─ TYPE = 0x05 (PING)
```

车回 `PONG`，车 `SEQ=0D`，uptime 12345 ms = `0x3039`：

```
AA 55 0F 0D 04 39 30 00 00 89 0D 0A
                     └──┬──┘  └─ SUM = 0F+0D+04+39+30+00+00
                   uptime_ms（小端）
```

其余指令和回帧的示例见 §3 各小节与 §10.2。

### 10.2 车 → 上位机实例

`SEQ` 和 `SUM` 每次不同，这里只用于对照格式：

| 帧                   | 含义                     | 实例                                             |
| -------------------- | ------------------------ | ------------------------------------------------ |
| `ACK` OK           | 确认 `CMD_MOVE seq=5`  | `AA 55 00 0A 03 03 05 00 15 0D 0A`             |
| `ACK` 被拒         | `CMD_VEL` 因控制源被拒 | `AA 55 00 0B 03 01 03 03 15 0D 0A`             |
| `ACK` 不支持       | 未知类型 `0x42`        | `AA 55 00 0C 03 42 09 02 5C 0D 0A`             |
| `PONG`             | uptime 12345 ms          | `AA 55 0F 0D 04 39 30 00 00 89 0D 0A`          |
| `EVENT` 急停       | code=2, data=0           | `AA 55 06 0E 02 02 00 18 0D 0A`                |
| `MOVE_DONE` OK     | `CMD_MOVE seq=5` 跑完  | `AA 55 08 0F 03 03 05 00 22 0D 0A`             |
| `MOVE_DONE` 被打断 | 同上，被新指令打断       | `AA 55 08 10 03 03 05 03 26 0D 0A`             |
| `FIELD_STATUS`     | 出生点 2、红             | `AA 55 01 11 02 02 01 17 0D 0A`                |
| `STATE`            | 控制源=上位机            | `AA 55 02 12 07 01 00 00 39 30 00 00 85 0D 0A` |

### 10.3 边界情况

| 操作                                                | 预期                                          |
| --------------------------------------------------- | --------------------------------------------- |
| 动作中发 T8                                         | `MOVE_DONE(03 05 03)` + `EVENT` + `ACK` |
| 动作中发 T2                                         | `MOVE_DONE(..3)`，随后保持停车              |
| T1 和 T3 连在一起发                                 | 两条都解析成功，回 `PONG` 且车动起来        |
| 先发 `AA 55 05 01 00`，100 ms 后再发 `06 0D 0A` | 补全后才回 `PONG`                           |
| 先发 `AA 55 7F 00 00`，再发 T1                    | 丢 1 字节重同步，T1 正常回 `PONG`           |
